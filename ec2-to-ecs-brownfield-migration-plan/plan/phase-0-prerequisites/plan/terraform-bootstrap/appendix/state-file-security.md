# Appendix: State File Security

Security considerations and best practices for protecting Terraform state files.

## What's in a State File?

State files contain **sensitive data** that could aid an attacker:

- Database passwords (if not using secrets manager)
- Private keys (if generated by Terraform)
- Resource IDs and network topology
- Configuration details of your infrastructure
- IP addresses and CIDR blocks
- ARNs of IAM roles and policies

## Security Risks

**If state files are compromised:**

- ❌ Attacker learns your complete infrastructure layout
- ❌ Secrets hardcoded in Terraform become exposed
- ❌ Network topology reveals attack surface
- ❌ Resource naming conventions leak organizational structure

## Mitigation Strategies

### 1. Never Commit State Files to Git

**Add to `.gitignore`:**

```gitignore
# Terraform State (Local)
*.tfstate
*.tfstate.*
*.tfstate.backup
```

**Why:**

- Git history is permanent (even after deletion)
- Public repositories expose state to anyone
- Accidental pushes difficult to undo

### 2. Use AWS Secrets Manager for Sensitive Values

**Instead of:**

```hcl
resource "aws_db_instance" "main" {
  password = "hardcoded-password"  # ❌ BAD - ends up in state file
}
```

**Do this:**

```hcl
data "aws_secretsmanager_secret_version" "db_password" {
  secret_id = "prod/db/master-password"
}

resource "aws_db_instance" "main" {
  password = data.aws_secretsmanager_secret_version.db_password.secret_string  # ✅ GOOD
}
```

**Result:** State file contains secret ARN, not the actual password.

### 3. Restrict S3 Bucket Access

**Principle of Least Privilege:**

```hcl
# Only CI/CD service accounts and platform engineers
resource "aws_s3_bucket_policy" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid    = "DenyUnencryptedObjectUploads"
        Effect = "Deny"
        Principal = "*"
        Action = "s3:PutObject"
        Resource = "${aws_s3_bucket.terraform_state.arn}/*"
        Condition = {
          StringNotEquals = {
            "s3:x-amz-server-side-encryption" = "AES256"
          }
        }
      },
      {
        Sid    = "AllowOnlyServiceAccounts"
        Effect = "Allow"
        Principal = {
          AWS = [
            "arn:aws:iam::${var.aws_account_id}:role/github-actions-terraform",
            "arn:aws:iam::${var.aws_account_id}:role/PlatformEngineer"
          ]
        }
        Action = [
          "s3:GetObject",
          "s3:PutObject",
          "s3:DeleteObject"
        ]
        Resource = "${aws_s3_bucket.terraform_state.arn}/*"
      }
    ]
  })
}
```

### 4. Enable CloudTrail Logging

**Monitor state file access:**

```hcl
resource "aws_s3_bucket_logging" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  target_bucket = aws_s3_bucket.logging.id
  target_prefix = "terraform-state-access-logs/"
}
```

**Alerts for suspicious activity:**

```hcl
resource "aws_cloudwatch_metric_alarm" "unusual_state_access" {
  alarm_name          = "terraform-state-unusual-access"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 1
  metric_name         = "StateFileDownloads"
  namespace           = "TerraformState"
  period              = 300
  statistic           = "Sum"
  threshold           = 10
  alarm_description   = "Unusually high number of state file downloads"
}
```

### 5. Enable S3 Versioning and Object Lock

**Versioning for recovery:**

```hcl
resource "aws_s3_bucket_versioning" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  versioning_configuration {
    status = "Enabled"
  }
}
```

**Object Lock to prevent deletion (optional, for compliance):**

```hcl
resource "aws_s3_bucket_object_lock_configuration" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  rule {
    default_retention {
      mode = "GOVERNANCE"  # Admins can still delete with special permission
      days = 30
    }
  }
}
```

### 6. Encrypt State at Rest and in Transit

**Server-side encryption (already in bootstrap module):**

```hcl
resource "aws_s3_bucket_server_side_encryption_configuration" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"  # Or "aws:kms" for customer-managed keys
    }
  }
}
```

**KMS encryption for additional control:**

```hcl
resource "aws_s3_bucket_server_side_encryption_configuration" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm     = "aws:kms"
      kms_master_key_id = aws_kms_key.terraform_state.arn
    }
  }
}

resource "aws_kms_key" "terraform_state" {
  description             = "KMS key for Terraform state encryption"
  deletion_window_in_days = 10
  enable_key_rotation     = true

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid    = "Enable IAM User Permissions"
        Effect = "Allow"
        Principal = {
          AWS = "arn:aws:iam::${var.aws_account_id}:root"
        }
        Action   = "kms:*"
        Resource = "*"
      },
      {
        Sid    = "Allow Terraform State Access"
        Effect = "Allow"
        Principal = {
          AWS = "arn:aws:iam::${var.aws_account_id}:role/github-actions-terraform"
        }
        Action = [
          "kms:Decrypt",
          "kms:Encrypt",
          "kms:GenerateDataKey"
        ]
        Resource = "*"
      }
    ]
  })
}
```

**Enforce encryption in transit:**

```hcl
resource "aws_s3_bucket_policy" "terraform_state" {
  bucket = aws_s3_bucket.terraform_state.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid    = "DenyInsecureTransport"
        Effect = "Deny"
        Principal = "*"
        Action = "s3:*"
        Resource = [
          aws_s3_bucket.terraform_state.arn,
          "${aws_s3_bucket.terraform_state.arn}/*"
        ]
        Condition = {
          Bool = {
            "aws:SecureTransport" = "false"
          }
        }
      }
    ]
  })
}
```

## State File Audit Checklist

- [ ] `.gitignore` excludes all `.tfstate` files
- [ ] S3 bucket has server-side encryption enabled
- [ ] S3 bucket blocks public access
- [ ] S3 versioning enabled for disaster recovery
- [ ] CloudTrail logging enabled for state bucket access
- [ ] IAM policies restrict state access to service accounts only
- [ ] Secrets stored in AWS Secrets Manager, not hardcoded
- [ ] MFA enabled for production state bucket access (if applicable)
- [ ] Regular audits of state file access logs
- [ ] Incident response plan for state file compromise

## What to Do if State is Compromised

**Immediate Actions:**

1. **Revoke access** to compromised credentials/tokens
2. **Rotate secrets** that may be in the state file
3. **Review CloudTrail logs** for unauthorized state file access
4. **Inspect state file** to identify exposed resources
5. **Update passwords** for databases, API keys, etc.
6. **Enable GuardDuty** if not already active

**Long-term:**

1. Implement KMS encryption for state files
2. Audit IAM policies granting state access
3. Move secrets to AWS Secrets Manager
4. Set up CloudWatch alarms for unusual state access patterns
5. Document incident in security log
